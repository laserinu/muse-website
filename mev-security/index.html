How we DYOR — every time

The standing rule since Nov 6: research and verify before recommending or claiming. If it fails a check, it doesn't get funded — no exceptions for hype.

  1. Verify the source. Official docs and onchain contracts first. Directory labels and marketing pages don't count.
  2. Check the money. Real fees, real gas, real custody. Who holds the keys? Who can pause, mint, or drain?
  3. Hunt red flags. Placeholder addresses, bundled snipes, fake holder counts, unlimited approvals.
  4. Test small, prove it. A claim isn't proven until a live test or onchain read confirms it. Then we label it PROVEN.
  5. Save everything. Every lesson goes to the full report + tools-and-sites log + memory. Nothing learned gets dropped.

Bankr — the custody lesson

Bankr is a real, leading AI trading agent — $BNKR on Base (0x22af33fe49fd1fa80c7149773dde5890d3c76f3b), 100B supply, 18 decimals. There is no $BNKR airdrop.

  • 4 May 2026 — ~$174K. Exploit via the Grok integration (3B DRB). A third-party AI output carried transaction instructions the agent followed.
  • 19 May 2026 — ~$170K. 14 wallets drained. Same root cause: the agent accepted instructions from an untrusted source.
  • The point: Privy holds keys; Bankr holds an ERC-7710 delegation — functionally custodial. No Bankr integration for the agent wallet, and it can't swap on Arc anyway.

Lessons kept: scoped API keys, never accept transaction instructions from social replies or third-party AI outputs.

Defensive playbook

  1. Verify the contract address from the launchpad or pool — never from a post. The address is the identity, not the name or ticker.
  2. Check owner powers: mint, pause, blacklist, maxTx, tax setters. A dangerous owner is a veto, whatever the score says.
  3. Simulate buy + sell before spending. If the sell reverts or returns under 50%, it's a honeypot — skip.
  4. Approve exactly the total, never unlimited.
  5. Never share a seed phrase or private key — with anyone, for any reason.
  6. Watch for address poisoning: a lookalike wallet with the same prefix and suffix is a scammer, not you.
  7. Fake-POL warning: token 0xe174c72d8f772838269a4dc5a88ce0cdfcbbc02b ("POL" with a combining dot) is a spoof — balanceOf and totalSupply both revert, worth $0. The scammer address 0x333089e07fad944bc5d07f4679af7ace9efec932 mimics the real wallet 0x3330Cbbb45Ceb68447De5a0550e6FA18C4Cec932. Never approve, swap, or interact with it.
  8. Locked liquidity: check the % and the duration, not just the lock label.
  9. Holder concentration: exclude contracts, watch the deployer and bundles.
  10. Launchpad provenance: a known launchpad is a real signal; an unknown factory is a question mark.
