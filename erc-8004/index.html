What ERC-8004 actually is

EIP-8004 is a draft standard for trustless agents. It defines three registries that work together — and it is designed to sit alongside A2A agent communication, MCP tooling, and x402 payments, not replace them.

Registry 01 — Identity

An ERC-721 NFT is your Agent ID. Portable across chains, owned by your wallet, pointed at a registration file that says who the agent is and what it does. This guide is about this registry.

Registry 02 — Reputation

Anyone who works with your agent can leave onchain feedback. Over time that becomes a public track record — the reason a stranger might trust your agent over an anonymous one.

Registry 03 — Validation

Independent checks on the agent's work: TEE attestations, zkML proofs, staking-backed validation. Heavier machinery — you don't need it to register, but it's where serious agent work is heading.

Draft means draft. ERC-8004 is not Final yet, so the spec can still change. Registrations already minted are real ERC-721s on real chains — they don't disappear if the spec evolves — but don't treat any tooling around it as settled forever. Check 8004scan.io for the current chain list (29 chains at the time we registered).

Before you start

  1. An agent wallet you control. Ours is a Privy agent wallet the agent itself transacts from. Any EVM wallet works — but see the rule below about registering from that wallet.
  2. A little gas on each target chain. Registration is one transaction. On Base ours cost 0.00000426 ETH; on Robinhood Chain ~0.00009325 ETH. You need native gas on the chain, not tokens.
  3. A name, a one-paragraph description, and an image. That's your public profile. Use your real agent image — ours is the fluffy headphone character, submitted consistently everywhere the identity appears.
  4. Ten minutes per chain. The Base registration itself was minutes. Most of the evening went on funding four chains with gas — the registrations were the easy part.
The one rule that saves you a second transaction: Register FROM the agent wallet itself. When you call register(), the new Agent ID's agentWallet defaults to the address that sent the transaction. Register from your agent wallet and owner = agentWallet automatically — done in one step.

Register from a different wallet and you'll have to call setAgentWallet afterwards, which requires an EIP-712 signature from the new wallet to prove you control it. It works, but it's an extra signed step people trip over. Start from the right wallet.

The registration file

Everything public about your agent lives in one JSON file — the agentURI points at it. Ours is the registration-v1 format from the spec. Strip the image to a hosted URL or a small data URI; don't paste megabytes of base64 into a guide, host it properly or keep it lean.

{
  "type": "https://eips.ethereum.org/EIPS/eip-8004#registration-v1",
  "name": "Muse",
  "description": "Muse is a personal AI agent for 0xlinu. Airdrop DYOR agent: researches and verifies airdrops, tracks entries and results, and works multichain across EVM networks. Owner: 0xlinu. Agent wallet: 0x0A1D2730f4Ae736Bac3D772FaB8607BFd7F650C4 (Privy agent wallet, Base).",
  "image": "https://…/muse-fluffy-logo.png",
  "active": true,
  "x402Support": false,
  "supportedTrust": ["reputation"],
  "services": [
    { "name": "DID", "version": "v1",
      "endpoint": "did:pkh:eip155:8453:0x0A1D2730f4Ae736Bac3D772FaB8607BFd7F650C4" }
  ],
  "registrations": [
    { "agentId": 1166847, "agentRegistry": "eip155:8453:0x8004A169FB4a3325136EB29fA0ceB6D2e539a432" },
    { "agentId": 391488,  "agentRegistry": "eip155:5042:0x8004A169FB4a3325136EB29fA0ceB6D2e539a432" },
    { "agentId": 696,     "agentRegistry": "eip155:137:0x8004A169FB4a3325136EB29fA0ceB6D2e539a432" },
    { "agentId": 21484,   "agentRegistry": "eip155:4663:0x8004A169FB4a3325136EB29fA0ceB6D2e539a432" }
  ]
}

Field notes: registrations starts empty on your first chain — you fill each entry in after that chain mints. services is where you advertise how to reach the agent (DID, A2A, MCP, web endpoint). supportedTrust declares which trust models you claim — don't list validation until you actually have validators.

How to publish the file (your agentURI)

Hosted HTTPS / IPFS URL — best for most people. Put the JSON on a stable URL and use that URL as the agentURI. Easy to update later with setAgentURI.

data: URI — what we used first. Encode the whole file as data:application/json;base64,… and it lives entirely onchain. No hosting, no pinning — but every update is a new onchain transaction with the full file again.

The setup, step by step

One chain at a time. Do Base (or your cheapest chain) first, confirm it appears on 8004scan, then repeat — the process is identical everywhere because the registry is deployed at the same address on every mainnet.

Identity Registry · Mainnets: 0x8004A169FB4a3325136EB29fA0ceB6D2e539a432
Identity Registry · Testnets: 0x8004A818BFB912233c491871b3d84c89A494BD9e

Same CREATE2 address on every supported mainnet — verify it once on the chain explorer (on Basescan it's labelled "8004: Identity Registry", token AgentIdentity (AGENT): basescan.org/address/0x8004A169…) and reuse it. Only ever register against this address. Lookalike registries are the obvious scam here.

Step 1 · Build and publish your registration file

Write the JSON above with your agent's name, description, image, and services. Leave registrations as [] for the first chain. Publish it and copy the URL — or build the data URI:

# turn the file into a data URI (our first agentURI)
base64 -w0 muse-agent.json | sed 's|^|data:application/json;base64,|' > muse-agent-data-uri.txt
cat muse-agent-data-uri.txt

Step 2 · Fund the agent wallet with gas — on that chain

Send a small amount of the chain's native token to the agent wallet itself (not to the address that will "help" register — remember the rule). On Base, well under 0.001 ETH covers registration many times over. On Polygon you'll need POL; on Arc, USDC is the native gas token.

Polygon warning from our run: gas there spiked to 232–255 gwei, and a later setAgentURI update needs roughly 4M gas. Register when gas is calm, or be ready to wait — our Polygon profile update is still queued for ≤40 gwei rather than overpaying.

Step 3 · Call register(agentURI) — from the agent wallet

One transaction mints the Agent ID. Two ways to send it:

Route A — explorer (you sign in your wallet): Open the registry on the chain explorer → Write Contract → connect the agent wallet → register → paste your agentURI → confirm. Best for a first, human-checked registration.

Route B — agent sends it (what we did, via the Privy CLI): The agent prepares the exact call and you review it before it goes:

# restore the pinned machine identity first (see the Privy wallet guide),
# then send register(agentURI) to the Identity Registry on Base (8453)
privy-agent-wallet rpc --json '{ "method": "eth_sendTransaction", "caip2": "eip155:8453", "params": { "transaction": { "to": "0x8004A169FB4a3325136EB29fA0ceB6D2e539a432", "chainId": 8453, "data": "<register(agentURI) calldata>" }} }'

The calldata is just the ABI encoding of register(string) with your URI — any ABI tool or explorer's read/write UI will generate it. Double-check to is the canonical registry before confirming. Registration moves no funds except gas.

Step 4 · Read your Agent ID from the receipt

The Registered event in the transaction receipt carries your new agentId. That number is the identity — Base gave us 1166847, Robinhood Chain gave us 21484. Save it with the chain ID and the transaction; you'll need the exact pair for the next step.

Step 5 · Update the file, point the NFT at it, verify

Add the new entry to registrations in your JSON:

{ "agentId": 1166847, "agentRegistry": "eip155:8453:0x8004A169FB4a3325136EB29fA0ceB6D2e539a432" }

Republish the file. If your agentURI is a hosted URL and the content changed in place, you're done. If it's a data URI (or the URL changed), call setAgentURI(agentId, newURI) from the owner wallet — we verified the tokenURI matched after doing this on Base and Robinhood Chain, and confirmed success on Arc.

Then check yourself the way a stranger would: search your wallet on 8004scan.io and confirm the name, image, and description render correctly. If 8004scan can't read it, nobody else can either — fix the file, not the listing.

After registration

  • Repeat per chain, deliberately. Each chain is a separate NFT with a separate ID. We did four — Base first, then Arc and Polygon eight minutes later, Robinhood Chain once its gas was bridged in. There's no bulk register; that's fine, identity per chain is the design.
  • Keep the profile consistent. Same name, same image, same owner line on every chain and every explorer submission. Consistency is what makes four NFTs read as one agent.
  • Let reputation accumulate. Anyone can leave feedback through the Reputation Registry. Don't farm it, don't self-review — the registry is only useful if the feedback is real work from real counterparties.
  • Explorer "creator" ≠ owner. On Etherscan-style explorers, a token or identity deployed through a contract may display the transaction sender as creator. That's a display convention, not your registration being wrong — the registry's owner/agentWallet fields are the source of truth.

Safety checklist

  • Only the canonical registry. 0x8004A169FB4a3325136EB29fA0ceB6D2e539a432 on mainnets. Verify the label on the chain explorer before you sign — never follow a registry address from a random post.
  • Never share a seed phrase or private key — with a registration service, a "verification" site, or an agent. Registration needs a signature, never a key.
  • Review the exact call before sending. register() should go to the registry, carry only your URI, and move no value beyond gas. Anything else in the transaction is a reason to stop.
  • Keep the owner wallet safe — it IS the identity. Whoever controls the owner wallet controls the Agent ID NFT: its URI, its agentWallet, its transfer. Treat that wallet's security as your agent's security.
  • Backup path is a different identity. Registering the same file from a backup wallet (we kept one ready) mints a different Agent ID under that wallet. Useful in an emergency, but don't present two IDs as one agent without saying so.
